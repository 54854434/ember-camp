# v1存档与恢复

文件为`user://camp_v1.json`及`.bak`；不改变Android包名。使用Godot 4.4.1标准版；用户数据目录不属于源码仓库。

## 候选与迁移

SaveValidator接收Variant，先检查字典根对象和版本，再深拷贝校验/迁移。拒绝错误类型、非有限数值、非法数量/物品、建筑/营地/运单断裂；不靠夹紧负库存或补送开局物资修复坏档。未知额外字段保留，未知物品/建筑拒绝。验证失败不修改游戏世界。

- hp/stamina/hunger范围0—100，threat为0—110；整数量必须无小数，弹匣0—12、炮台余弹0—24，发电计时0—120。计数非负、day至少1；坐标有限，格坐标在Vector2i范围内。
- 每个营地有名称、格坐标、库存；每个营地坐标必须有所属核心，不得重叠。建筑种类、耐久、所属营地与门状态需有效。
- 运单source/target必须存在且不同，货物为正整数已知物品，时间非负、风险0—1、遇袭结果为bool。保存遇袭结果，加载不重抽。
- 旧单营地v1缺少camps时，从原stash/threat/camp_cell建立原有营地；缺少camp_cell时使用旧原点约定，不重定位已保存核心。
- 旧多营地v1缺少局部余弹/计时时，仅保存时的活跃营地继承全局字段，远方营地为0；现代局部值优先。
- `tests/fixtures/save_v1_legacy.json`和`save_v1_network.json`是按旧格式编写的兼容样本，不是用户私人存档或由新序列化器自动生成的金样。

## 写入与故障

先校验快照，再写`.tmp`、flush并回读。有效旧主档复制到`.bak.tmp`并校验，替换`.bak`后再替换主档；所有可报告的文件错误均返回失败。损坏主档不得覆盖已存在备份，临时文件不自动当成已提交进度。

加载按主档、备份顺序。备份成功时明确提示可能丢失最近一次保存。两个已有文件均不合法时，保留当前世界和磁盘文件，阻止该路径自动/手动保存；成功重新加载修复后的文件才解除。此时显示的是临时会话，不能依赖其新进度被保存。没有任何文件是正常首次启动。

这些措施不提供文件系统fsync目录日志或跨平台断电零丢失保证。缺少校验和时无法识别所有“仍符合schema的错误数值”。当前仍是全量JSON，区域存档与完整动态敌人快照另见路线图。
