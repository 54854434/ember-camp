# 后期交付与平台复盘

用于把 ComfyUI 镜头剪成可审、可发和可复盘的短视频。按任务选用相应部分。当前任务只需要方法时，交付空白记录字段。

## 先拼故事，定位最低成本的修复

以已确认分镜为底稿，用可用的视频、静帧和临时对白拼出一版完整时间线。先过一遍观众会依次看到和听到什么，用「时间码、观察到的问题、影响、修复动作」记录。补镜前检查相邻镜头的动作起止、视线和声音。

| 粗剪观察 | 先验证哪种修复 |
| --- | --- |
| 缺少关键事实，观众看不懂结果 | 找现有镜头是否早已给出该事实。能通过前移细节、反应或调整对白顺序解决时先试；否则补一镜可见的证据 |
| 镜头里有正确动作，剪接后动作突然跳变 | 检查运动方向、动作阶段、道具位置和两侧实际可用帧。试在动作过程中换镜，用相匹配的帧衔接；有叙事理由时插入道具特写或接收者反应 |
| 对白有音量断层或含糊 | 先分轨处理人声、环境、音效与配乐。只修有问题的片段，听降噪是否损伤字头，核对嘴型、语气和上一镜的环境底声 |
| 关键动作没发生、人物变脸或承接关系错误 | 回到对应镜头的提示词和参考版本，优先补生成受影响镜头。人物、参考图、种子、生成参数和邻接状态要能追溯 |

按实际可用画面选择工具。剪映公开功能包含声音分离、降噪和响度统一；先后试听，细节是否保留以导出的片段为准。微短剧把关可放在故事、可用镜头与成片三个实际交接点，优先解决会影响下一步的问题。 [剪映官方功能](https://www.capcut.cn/) · [中国网络视听节目服务协会的微短剧制作讨论](https://www.cnsa.cn/art/2026/8/12/art_1955_49163.html)

## 从剪辑母版派生发布版本

- 留可编辑工程与干净的视频母版，按需要保留对白、底声、音效和配乐分轨及字幕文本。两平台版用各自目标画幅重排。优先检查首帧是否识别得出主体、关键信息是否被界面挡住、手机扬声器上对白是否听清。
- 每个发布版本关联成片文件、字幕或字幕版本、封面、文案、账号与工作底稿。平台文案承诺的包袱、反转或信息用导出文件实看。需要发布规格、AI 声明、权利或短剧交付要求时，使用当期平台后台和[平台规则核查](research-and-update.md)。
- 发布后若看到平台端成品，检查实际压缩、字幕和封面显示。版本差异写清是片头、时长、画幅、包装还是混音，便于之后把留存掉点对回对应时间线。

## 用国内平台能看到的指标做判断

抖音先看该账号作品分析里实际展示的早期观看和流量来源。B 站可结合可见的平均播放进度、观众流失曲线及弹幕时间分布。两边按后台显示的名称与口径记录。若某项后台数据缺失，改用能支持当前判断的证据并写清范围。 [抖音创作者中心](https://creator.douyin.com/) · [B 站数据中心使用说明](https://www.bilibili.com/blackboard/activity-0ONDyIXVCl.html)

| 后台观察 | 回看什么 | 下轮只测一个主要改动 |
| --- | --- | --- |
| 点击弱，但进入后留存与账号同类作品接近 | 曝光入口是否相近，封面标题在小屏上确认了什么 | 调整封面主体或标题里的一个承诺 |
| 开场出现明显流失 | 前几个节拍是否让观众看见人物正在遇到什么 | 提前一个有信息量的动作、道具或人物反应 |
| 中段某处掉点 | 掉点前一段的因果、对白密度和是否已经重复交代 | 删一段重复交代或补一个必要的反应镜头 |
| 某个时间段弹幕集中 | 弹幕在笑、疑惑、纠错还是讨论同一线索 | 根据实际留言决定复用笑点结构或补清楚叙事 |

比较时先选同平台、同账号、相近题材与时长、近似流量入口的基线，对齐发布后观察窗口。只有平台提供随机分流或有相当的实验设计时才称为 A/B 测试。不同作品的一次对照记录为观察结果，同时记下题材热度、投放、推荐来源或发布时段等变化。用自己的同类稿件分布判断表现，并记录账号、时间、样本和指标分母。

### 制作成本记录

当需要决定能否稳定连载时，按镜头记生成尝试次数、实际生成时间、人工挑片与返工分钟、最终采用秒数。可用「生成总分钟 ÷ 实际剪进成片的独立有效秒数」比较同样质量目标下的生成负担，人工时间单列。有效秒数为零时记未出片，并保留已花时间和失败原因。看哪些类型反复超预算，下一次优先调整其设计、声音处理或拍法。
