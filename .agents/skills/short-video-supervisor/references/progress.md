# 进度与续作

任务有几个可识别的阶段，或需要多次操作才能交付时，让用户在聊天中知道进度。简单问答、单处文案修改或能直接交付的单条提示词跟随本次请求的输出方式。

## 开始时列出实际步骤

先用一行写本次交付和阶段顺序，通常三到四步就够。随后注明「正在 1/3」及正在处理的内容。按实际任务选择阶段和总数。

| 任务 | 可以采用的阶段 |
| --- | --- |
| 一句话扩展成完整或多段提示词 | 确认目标与素材 → 编排分镜与接点 → 写提示词并核对格式 → 交付 |
| 看样片修提示词 | 核对样片与原提示词 → 找到首个偏差 → 修改受影响段落 → 核对或复验 |
| 学习资料并更新技能 | 核对来源 → 筛选可迁移方法 → 更新对应文件 → 同步并核验 |

只有本次确实包含生图、出视频、试听、格式检查或同步时，才把相应动作写进阶段。阶段名用用户看得懂的产出或检查命名，聊天进度与可用的进度面板保持一致。

## 每次更新都带上可核实的进展

- 开始下一阶段时，用一句话写「正在第 2/4 步 · 编排分镜。已核对两张参考图，接下来逐个定段间切点。」任务较长时，遇到会影响结果的发现或需要等待的操作也更新一次。连续进行的例行操作合在一条进度里。
- 当前步骤的编号表示正在做哪一步。只有实际完成该步的产出和检查后，才标为已完成。如果用户改了范围，简短说明为什么重排步骤和新的总数。
- 出现阻塞时写清卡在哪一步、缺少什么、哪些工作可继续。用户问「到哪一步了」时，直接报当前步骤、最近已完成的一项和下一步。状态写事实和产出，内部逐拍稿和评审过程按用户实际要求交付。

## 继续与交付

- 收到「继续」时，先核对本次任务的上一条进度、已交付文件或实际运行结果。用一句「已完成 X，正在接着做 Y」恢复工作，沿用已确认的素材和决策。上轮交付已经完成时，从用户指向的下一项开始。新对话里的进度以当前可访问的项目记录为依据。
- 交付时先给用户要用的结果，再简短列明实际验证和只有拿到样片才可确认的项目。举例来说，提示词通过 1160 格式检查属于已验证，成片的口型和衔接仍须看实际视频。用户明确只要正文时，成果区保留完整可复制的正文，必要状态用此前的聊天进度交代。
