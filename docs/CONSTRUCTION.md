# 施工与空间查询

场景施工命令在scripts/construction_controller.gd；空间判定在scripts/world_occupancy.gd。当前是同步命令与实时字典查询，不是全局寻路、导航网格或完整世界索引。

## 对外入口

| 方法 | 责任 |
|---|---|
| build_error | 施工预览/错误查询，不扣材料或修改世界 |
| build | 重新查询完整条件后调用规则层一次提交 |
| dismantle | 距离校验后按归属/核心规则拆除和返材 |
| settle | 地形、设施、敌人、距离校验后初次落营或消耗携带物资建前哨 |
| toggle_gate | 距离与关门时的角色占用校验后切换门状态 |

Survival的build/settle/found_outpost/dismantle/toggle_gate为低层规则事务，隔离规则测试可以直接调用；新场景功能须经ConstructionController，不能绕过世界校验。建造执行与状态提交之间没有await，不把预览成功缓存为执行许可。

## 占用和通行

- 建筑实体碰撞使用原54×54范围，门关闭阻挡、打开通行；尖刺等可通行设施仍保留施工格，不能原地叠建。
- 施工距离480；普通施工检查敌人距中心65。扎营地形缓冲65，敌人缓冲220；原有领地、科技、保留通道与材料规则保持。
- 移动、弹道及炮台视线继续调用Main.solid_at，内部委托共享查询；玩家/敌人半径沿用18/15。
- 关闭营门前检查门框内的玩家和敌人；失败不修改门状态。开启无需清空门框。
- 查询直接读取structures，不保存第二份占用缓存；开门、拆除、摧毁、恢复与初始核心迁移之后立即生效。原点迁出的核心不留阻挡，新建前哨不移除原主营地。
- 施工所需块若不在chunks，只计算原v1静态地形，不改变活动块、生成顺序、敌人驻留或存档。敌人占用来自现场enemies。

## 验证和限制

tests/test_construction.gd有57项检查，覆盖规则/资源守恒、动态占用、实际场景入口、门状态/读档、负坐标与缺失块查询、核心和前哨。由统一隔离检查入口执行。

全局可达性、丧尸代价寻路、复杂墙阵和整个营地出口连通性尚未完成。没有真实设备性能数据，不宣称该查询结构提升帧率。现有容器交互、世界修改存档和角色移动模型仍由既有模块负责。
